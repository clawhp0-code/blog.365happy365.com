미국 경제를 살펴볼 때 금리와 물가, 고용, 성장률 자료를 매번 따로 찾으면 비교 기준이 흔들리기 쉽다. 이번에는 FRED API를 연결해 네 가지 경제지표를 같은 절차로 수집하도록 구성했다. **API 키 발급에 이어 실제 데이터 조회와 파일 저장까지 확인했다.** 이 글은 2026년 10월 31일 작업 기준의 연결 기록이며, 특정 시점의 경제 수치를 전망하는 글은 아니다.

## FRED는 어떤 서비스인가

FRED는 Federal Reserve Economic Data의 약자로, 미국 세인트루이스 연방준비은행이 운영하는 경제 데이터 서비스다. 여러 기관의 경제 시계열을 조회할 수 있으며, API를 이용하면 프로그램이 필요한 자료를 받아 가공할 수 있다. 공식 API는 HTTPS로 요청하고 JSON 등의 형식으로 결과를 돌려준다. 원자료 작성기관은 지표마다 다르므로 FRED와 해당 통계의 출처를 함께 확인하는 것이 좋다. ([FRED API 소개](https://fred.stlouisfed.org/docs/api/fred/overview.html))

## 처음 연결한 경제지표 네 가지

- **FEDFUNDS**는 월평균 실효 연방기금금리다. 연방공개시장위원회가 정하는 목표금리 범위와 구분해 읽어야 한다. ([지표 설명](https://fred.stlouisfed.org/series/FEDFUNDS))
- **CPIAUCSL**은 계절조정한 도시 소비자물가지수다. 지수 수준 자체는 전년 동월 대비 물가상승률과 다르며, 상승률을 구하려면 비교 기간을 정해 변화율을 계산해야 한다. ([지표 설명](https://fred.stlouisfed.org/series/CPIAUCSL))
- **UNRATE**는 계절조정 실업률로, 노동력에서 실업자가 차지하는 비율을 나타낸다. ([지표 설명](https://fred.stlouisfed.org/series/UNRATE))
- **GDP**는 분기별 명목 국내총생산이며 단위는 십억 달러, 계절조정 연율이다. 실질 경제성장률과 같은 값으로 해석하면 안 된다. ([지표 설명](https://fred.stlouisfed.org/series/GDP))

월별 지표 24개와 분기별 지표 24개는 포함하는 시간 길이가 다르다. 이번 수집의 ‘최근 24개’는 동일 기간을 뜻하는 대신 각 시계열의 최근 관측값 수를 뜻한다.

## 96개 관측값과 저장 결과를 확인했다

연결 테스트에서는 네 지표를 차례로 조회해 각각 최근 관측값 24개, **총 96개**를 받았다. 수집한 자료가 JSON과 CSV로 저장되는지 확인했다. JSON은 지표별 구조와 설명을 보존하고, CSV는 표 계산 도구에서 값을 비교하기에 편리하다.

직접 성공 여부를 확인하려면 새 CSV의 파일 수정 시각을 보고, 헤더를 제외한 데이터가 96행인지 확인하면 된다. `series_id` 열에는 네 코드가 각각 24번 있어야 한다. JSON의 `retrieved_at_utc`는 UTC 기준 수집 시각이므로 한국시간과 비교할 때 9시간 차이를 반영한다. 파일이 생긴 것과 내용이 맞는 것을 함께 확인하는 절차다.

숫자만 저장하지 않고 지표 이름, 주기, 단위, 계절조정 여부와 갱신 정보를 함께 남겼다. FRED의 시계열 정보 API는 이런 메타데이터를 제공한다. 수치가 비슷해 보여도 단위와 조정 방식이 다르면 직접 비교하기 어렵기 때문이다. 결측값으로 쓰이는 `.`도 0으로 바꾸지 않는다. ([시계열 정보 API](https://fred.stlouisfed.org/docs/api/fred/series.html))

## 관측기간과 수집일을 나누어 읽기

데이터에 붙은 날짜가 모두 발표일은 아니다. 월별 자료의 월초 날짜나 분기 자료의 분기 첫날은 해당 관측기간을 나타낸다. 수집 시각은 프로그램이 자료를 가져온 때이며, 통계가 처음 공개된 때와 구분해서 기록한다.

수정치도 주의할 부분이다. FRED의 기본 조회는 현재 이용 가능한 정보를 기준으로 하므로 과거 수치가 처음 발표됐을 당시의 값과 다를 수 있다. 과거 투자전략을 검증한다면 ALFRED의 과거 시점 자료와 실제 발표 일정을 별도로 확인해야 한다. ([실시간 기간과 수정치 안내](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html))

## 키 보호와 자동 수집의 현재 단계

API 키는 공개 코드와 분리해 보관하고 Git에 포함되지 않도록 했다. 글이나 오류 로그에도 키 값을 남기지 않는 방식이다. FRED API는 요청 식별에 키를 사용하므로 예제 URL을 공유할 때도 실제 키를 넣지 않아야 한다. ([API 키 안내](https://fred.stlouisfed.org/docs/api/api_key.html))

자동 수집은 Codex 예약 작업으로 **평일 한국시간 오전 6시 50분**에 실행되도록 설정했다. 10월 31일에는 예약 작업과 동일한 명령을 수동 실행해 정상 종료와 96개 관측값의 파일 저장을 확인했다. 첫 예정 실행은 11월 2일 월요일이다. 예약 시각에 자동으로 시작되는지는 아직 검증하지 않았으며, 첫 실행 후 실행 기록과 새 파일 생성 여부를 확인할 예정이다. 매일 수집하더라도 월별·분기별 통계가 매일 새로 발표되는 것은 아니다. 앞으로 경제 보고와 블로그에서는 저장된 값의 관측기간과 출처를 확인한 뒤 분석에 활용한다.
